# 도메인 전환 · 로그인 · 인트로 정리 설계

## 의도

`solvi.win`을 유일한 운영 주소로 정리하고, 새 주소에서도 교사와 학생이 문제은행·로그인·학습지 제작을 자연스럽게 이어 가게 한다. 인트로의 첫 화면은 학생의 취약 유형 지도가 주인공이 되며, 그 바로 아래에는 점수만 남는 수업의 문제를 말하는 짧은 문장을 둔다.

## 결정

- 쌍둥이 문제 3개를 담으면 하단 담기 막대가 `쌍둥이 문제 3개를 담았어요. 바로 학습지로 만들까요?`라고 명시하고, 기존 `학습지로 만들기` 동작으로 이어진다. 브라우저 경고창은 쓰지 않는다.
- 운영 주소가 적힌 앱 메타데이터, QR·학생 안내의 기본 주소, 사이트맵·로봇, 패스키 Edge Function 기본 주소를 모두 `https://solvi.win`으로 바꾼다.
- WebAuthn 패스키는 RP ID(도메인)에 암호학적으로 묶이므로 `solvi.p-e.kr`에서 만든 패스키를 `solvi.win`으로 이전할 수 없다. 새 Edge Function을 `SITE_URL=https://solvi.win`으로 배포한 뒤 새 주소에서 다시 등록하도록 오류 문구와 운영 문서를 제공한다.
- 기존에 구현된 취약 유형 지도(`#tmap`)와 상호작용을 히어로로 복구한다. 감성 문구는 그 아래 `#why` 섹션에 독립적으로 둔다. 연결형 운영체제 설명은 기존 `#connect`에서 유지한다.
- 로그인 화면은 같은 UI 체계를 유지하되, 큰 화면에서는 정보와 폼이 균형 있게 정렬되고 좁은 화면에서는 과한 카드 여백 없이 위에서 아래로 읽힌다.

## 범위 밖

- 기존 패스키를 새 도메인에서도 로그인 가능하게 만드는 우회는 하지 않는다. 브라우저 보안 모델상 불가능하다.
- Supabase의 실제 비밀값 변경과 Edge Function 배포는 저장소 변경이 아니므로, 배포 직전 운영자 명령으로 수행한다.

## 확인 기준

- 쌍둥이 문제 추가 후 하단 막대에 안내 문구와 학습지 제작 버튼이 동시에 보인다.
- 공개 문서와 실행 기본값에 운영 주소로 `solvi.p-e.kr`이 남지 않는다.
- 소개 페이지 첫 화면에 유형 지도와 유형 선택 상호작용, 바로 아래 `#why` 문장이 있다.
- 로그인 화면이 1440px·390px에서 가로 넘침이나 입력칸 덮임 없이 읽힌다.
