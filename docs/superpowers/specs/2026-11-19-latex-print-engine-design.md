# 신규 자료의 브라우저 LaTeX 출력 설계

## 확정 요구

- 이미 만든 교재·학습지·모의고사는 HTML 출력과 기존 쪽수·QR을 유지한다. 날짜로 추측해 재분류하지 않는다.
- 새 자료만 원본 XeLaTeX 양식으로 만든다. 생성자의 컴퓨터 자원을 사용하고 별도 조판 서버·유료 API를 추가하지 않는다.
- 첨부 신명조·KoPubWorld Dotum Bold/Medium·HancomEQN을 그대로 사용한다. 원본이 지정한 STIX Two Math도 유지한다. 누락 시 대체하지 않는다.
- HWP 표지의 제목·과목명·필적확인 문구·기관명·유의사항을 수정할 수 있다. 학습지에서도 앞표지를 선택할 수 있다.
- 실제 쪽 나눔 결과에 QR 문항 목록과 표지 쪽 안내를 맞춘다. 구현 검증 후 PR을 올리고 병합하지 않는다.

## 접근 방식

처음 검토했던 별도 서버 방식은 사용자의 비용 제약으로 폐기했다. 수동 컴파일용 파일만 내려받는 방식도 기본 흐름으로 채택하지 않는다. 브라우저 Web Worker의 XeTeX·xdvipdfmx WebAssembly를 사용해 앱 안에서 PDF를 생성한다. GitHub Pages는 정적 파일을 제공하고 기존 Supabase는 QR 명세만 저장·조회한다.

## 호환성

출력 버전이 없는 자료는 항상 HTML이다. 새 생성과 명시적 복제에만 `printEngine: xelatex-v1`, `templateVersion: haewon-2026-v1`을 저장한다. 기존 자료의 이름·내용 편집은 엔진을 바꾸지 않는다. 새 교재는 원래 구성 ID에 고유 식별자를 더해 기존 구성을 덮어쓰지 않는다.

교재 PDF 명세는 정확한 교재/회차/간격과 출력 변형별로 보관한다. 채점 선택기에는 최종 PDF 쪽수를 사용한다. 같은 교재와 문항 묶음을 다시 출력하면 제출 잠금 키를 유지한다. 기존 HTML 높이표를 새 양식에 맞춰 재측정하지 않는다.

## 원본 양식

본문 템플릿은 첨부 6–10회 XeLaTeX preamble을 사용한다. 본문 신명조, 제목·문항 번호 KoPubWorld, 수식 HancomEQN/STIX 범위를 유지한다. 5지선다는 원본의 한 줄/3+2/세로 선지 매크로를 사용하고 다른 개수의 선지도 버리지 않는다. 보기·표·분수·MathML·그림·긴 지문을 변환한다. HTML 전체를 이미지로 찍어 PDF에 넣지 않는다.

HWP에서 용지 771.02×1116pt, 제목 Bold 25pt/장평 85%, 과목명 Bold 46pt, 본문 Medium 17pt를 확인했다. 종횡비를 유지해 A4에 맞춘 표지를 만들며 원본 예시 학교·기관·문구를 서비스의 사실로 복사하지 않는다. QR과 본문이 겹치지 않게 새 PDF의 본문 하단은 24mm를 확보한다.

## 실행과 저장

엔진·필요한 TeX 패키지는 정적 파일로 함께 제공한다. 외부 패키지 서버에 실행을 맡기지 않는다. 폰트 4개는 각 브라우저에서 한 번 등록하고 원본 해시를 확인해 IndexedDB에 저장한다. 원본 폰트를 공개 저장소나 서버에 업로드하지 않는다.

문서 모델을 제한된 LaTeX로 변환하고 Worker에서 조판한다. 실제 shipout 로그의 쪽·문항·번호·구간을 수집한다. 표지·차례의 쪽 안내와 전체 쪽수가 안정될 때까지 최대 세 번 조판한다. 생성 취소·창 닫기·시간 초과는 해당 Worker를 종료한다. 실패하면 HTML로 전환하지 않는다.

Supabase에는 개인 정보 없는 불변 명세만 저장한다. PDF·폰트·학생 이름·문서 원문은 보내지 않는다. 테이블 전체 조회·수정·삭제 권한을 공개하지 않고 개별 식별자로 조회한다. 학습지 QR은 원래 학습지 번호로 연결해 제출·배정·잠금 흐름을 유지한다. 교재 QR은 최종 페이지 문항과 인쇄 번호로 채점하고 여러 쪽 선택·로그인 복귀를 지원한다.

## 검증 및 배포 경계

원본 PDF/TeX 7쪽 대조, 5개 과목의 실제 브라우저 PDF, 실제 문제은행 CSS 분수, 교재 생성·저장·채점 명세, 1440/820/390 출력 설정, 기존 HTML 회귀를 검증한다. 운영 반영 전 `supabase/sql_27_latex_manifests.sql` 적용이 필요하다. 이번 작업에서 운영 DB 변경·사이트 배포·PR 병합은 하지 않는다. 실제 Safari·휴대폰 기기 및 종이 인쇄는 별도 확인 범위다.
