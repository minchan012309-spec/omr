## 기존 구조와 비교 조사

빌드 없는 HTML/JS, GitHub Pages, Supabase(PostgreSQL/RLS), 과목별 JSON/이미지와 지연 로드 코드다. `books.js`는 실측 높이로 쪽을 계획하고 미리보기·인쇄·이미지 PDF를 만든다. `lazy/admin.js`에는 이미 원생·보호자·반·시간표·상담·보강·수강료 청구가, `lazy/acad.js`에는 출결·단말·수납·알림장이 있었다. 별도 중복 메뉴 대신 기존 학원 운영과 교재 화면에 통합했다.

## 출력·다크모드 수정

- 시작 카드가 정의되지 않은 `--card`의 흰색 대체값과 다크 글자색을 함께 쓰던 문제를 `--surface/--t/--l`로 수정.
- 일반 체크박스 CSS가 `.sw`에 적용돼 40px 스위치가 20px 체크박스로 줄고 체크 표시·동그라미가 겹치던 문제 수정.
- 선택한 디자인의 밝은 배경/밝은 글자 대비 수정. 디자인 썸네일은 실제 종이처럼 항상 흰색.
- 학습지 미리보기 Shadow DOM이 화면용 반전 필터를 상속하던 문제 수정. 화면 UI는 다크, 종이는 흰색·원래 잉크색 유지.
- 개념 분해가 `.children`만 사용해 최상위 텍스트/인라인 노드를 버리던 경로 수정. 엔티티는 DOMParser에서 한 번 해석하며 특수문자를 중복 디코딩하지 않는다.
- 독립 HTML 교재에 빠졌던 로컬 한글/옛한글/원문자 폰트 정의 포함.
- 실제 번들에서 없던 ㉠·ⓐ 등의 기호는 Noto Sans CJK에서 443개 기호만 추린 약 52KB OFL 글꼴로 제공. 라이선스·출처·변경 이름은 `fonts/SolviSymbols-*`에 기록.
- 기존 검사기의 모든 원문자를 무조건 오류로 처리하던 오래된 규칙은 실제 번들 cmap 결손 검사로 수정.

## 국어 원고 편집

화법과 언어 교재함의 **국어 원고 편집**에서 화법·언어·독서·문학 영역별 개념/핵심 정리/예문 분석/지문·작품/문법·비교표/보기·선택지/해설 블록을 구성한다. 제목·본문·순서·새 쪽 시작·문단 번호·원문 행 번호·강조/밑줄을 편집한다. 내신형/평가원형 출력 설정, 학생용/교사용 미리보기·인쇄·PDF 저장과 HTML 내보내기를 제공한다. 학생용 HTML에는 정답·교사 메모 자체가 포함되지 않는다.

원고는 **계정별 이 기기 저장**이며 JSON 백업/가져오기를 제공한다. HTML 입력은 실행하지 않고 텍스트로 이스케이프한다. 새 원고는 기존 문제은행 책 정의/QR을 바꾸지 않는다. 클라우드 원고 공동 편집·배포/QR 자동 채점은 새 원고에 구현하지 않았다. 행 번호는 입력 줄바꿈 기준이며 화면에서 자동으로 접히는 모든 시각적 줄을 세는 기능은 아니다.

## 행정 기능

- 기존 원생 목록에 상태/반/검색/정렬을 유지하고 현재 필터에 맞는 CSV 다운로드, 수식 주입 방지.
- 통합 학생 상세에서 보호자·반·출결·상담·수납·기존 OMR/채점 기록과 정답률 변화·취약 유형 확인. 최근 최대 200회/출결 365건 등 조회 범위를 표시. 학부모 학습 보고서 인쇄.
- 조퇴 상태와 정확한 월말 날짜 조회. 2월·윤년의 존재하지 않는 31일 조회 문제 수정.
- 운영 업무: 담당자·기한·학생 연결, 일/주/월 반복, 완료 시 다음 업무 생성. 월말 반복의 기준 일자 보존, 중복 완료 방지.
- 상담 예약: 학생·담당자·시작/종료·유형·상태·메모, 한국 시각 변환과 DB 중복 예약 차단.
- 휴강/대체수업: 날짜·반·강의실·강사·사유, 학생/학부모 시간표와 운영 대시보드에 반영. 다른 대체수업 및 휴강을 반영한 날짜별 중복 검사와 DB 트랜잭션 검사.
- 정규 반 시간표의 종료 시간/중복 강사·강의실 검사.
- 월 일괄 수강료: DB 잠금·키로 중복 방지. 같은 이름의 다른 반/이름 변경·기존 제목형 청구와 호환. 안전한 RPC가 없는 구설치에서 직접 쓰기로 우회하지 않는다.
- 원장 화면에서 공동 계정의 강사/행정 역할 변경. 역할에 맞는 메뉴와 수납/학습 데이터 요청 분리.

## 데이터·권한·배포

`supabase/sql_24_operations.sql`은 데이터 삭제 없이 열/표/트리거/함수/제한 정책을 추가한다. 신규 설치용 `setup.sql`에도 포함했다. 기존 설치는 23번까지 적용된 상태에서 24번만 적용한다. **운영 적용 전 DB 백업과 복제 환경 검증이 필요하다. 이번 작업에서는 운영 DB에 적용하지 않았다.**

| 역할 | 운영·출결·상담 | 학습 기록 | 수납·결제 안내 설정 | 역할/학원 권한 설정 | 계정 발급 |
| --- | --- | --- | --- | --- | --- |
| 원장 | 허용 | 허용 | 허용 | 허용 | 학생·학부모 |
| 강사 | 허용 | 허용 | 차단 | 차단 | 학생 |
| 행정 | 허용 | 차단 | 허용 | 차단 | 원장에게 요청 |
| 학생·학부모 | 기존 자녀 인증 RPC 범위 | 기존 허용 범위 | 학부모 본인 청구 조회 | 차단 | 차단 |

기존 공동 강사는 기본 teacher 역할이 되어 수납 접근이 제한된다. 원장은 행정 담당 계정을 staff로 지정한다. 학생·학부모 계정 발급 함수가 RLS를 우회해 권한을 얻지 못하도록 DB 함수·자격정보 변경 트리거를 함께 보호했다. 학생/가입 신청 비밀번호 해시의 REST SELECT 권한을 제거했고 기존 비밀이 아닌 열은 유지했다. `teacher_settings`의 teaching 데이터는 유지하면서 pay/perms 하위 변경을 각각 수납/원장 권한으로 강제한다. 여러 학원의 학생·반 외래키 연결을 DB에서 차단한다. 감사 로그에는 작업자·표·행·작업 종류만 기록하며 상담 본문을 복제하지 않는다.

서비스 워커 버전과 코드 캐시를 갱신했다. 배포 산출물은 여전히 정적 파일이며 런타임 npm/서버가 필요 없다.

## 검증 재현

```sh
npm ci
npx playwright install chromium
npm test
python3 tools/hl/audit.py --all
```

테스트 러너는 임의의 localhost 포트에서 읽기 전용 정적 테스트 서버를 켜고 종료한다. PGlite는 메모리 PostgreSQL이며 실제 Supabase에 연결하지 않는다. Linux CI에는 Playwright `--with-deps` 설치를 설정했다. `PW`, `PGLITE`, `CHROME`, `BASE`로 기존 도구 경로/서버를 지정할 수 있다. 프로젝트는 빌드와 TypeScript를 사용하지 않아 빌드·타입 검사 명령은 없다. 대신 모든 실행 JS 구문과 실제 브라우저·SQL 경로를 검사한다.

## 남은 항목과 적용 한계

- 운영 Supabase 적용, 실제 PostgREST 배포 설정, 물리 프린터, iOS/Android 실기기, 실제 출결 단말 하드웨어, 결제/외부 문자·알림톡 발송은 미검증이다.
- 새로운 국어 원고의 서버 공동 편집/배포/QR 채점, 시간 기반 배경 자동화·자동 메시지 발송은 미구현이다. 기존 문제은행 교재의 배포/QR 및 기존 알림장은 유지한다.
- 새 국어 원고 출력의 평가원형은 자체 서식이며 평가원의 모든 공식 조판 규격을 동일 복제한 것이 아니다.
- 대규모 운영 데이터 전체 페이지 처리 및 실서비스 동시접속 부하는 시험하지 않았다. 기존 조회 상한은 유지했고 표시된 보고서 범위를 따른다.
- 정규 시간표의 충돌은 편집 시 검사하고, 상담/대체수업과 반복 업무/월 청구는 DB에서도 보호한다. 정규 반 편집의 다중 관리자 동시 저장 부하 테스트는 하지 않았다.
- 새 원고 편집은 국어 전용 별도 경로로 추가했으며 모든 기존 국어 개념서 내용을 새 편집기에 일괄 변환하지 않았다.
